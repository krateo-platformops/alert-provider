Manage Alerts as CRs:
  kubectl -n {{ .Release.Namespace }} get alerts

Alerts in any other namespace (a tenant's) are reconciled too, named <namespace>/<name> in HyperDX.
They mirror their state and notify, but never open an Incident or an RCA:
  kubectl get alerts -A

UPGRADE NOTE (create-once reconciler): the reconciler never updates an Alert's HyperDX tile after it
is first created. If you are upgrading from a version that seeded the old `error-log-volume` /
`warning-log-volume` defaults — or you authored any Alert before this version — those carry a stale
Lucene tile that never fires (this pipeline leaves SeverityText empty) and is NOT retrofitted by the
new image. Delete them so a correct SQL tile is recreated:

  kubectl -n {{ .Release.Namespace }} delete alert error-log-volume warning-log-volume --ignore-not-found

Alert `spec.where` is ClickHouse SQL over otel_logs (whereLanguage is pinned to sql). See
examples/alerts/ for the seeded defaults as CRs and the rules for writing your own.
